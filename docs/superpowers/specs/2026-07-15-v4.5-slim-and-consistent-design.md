# safe-code v4.5 — Slim & Consistent (design)

**Goal:** Cut the token weight of `skills/safe-code/SKILL.md` by extracting rare-path
procedure detail into Layer-3 references and deduplicating repeated prose, while fixing
every cross-file contradiction found in the 2026-07-15 audit. North star (owner's words):
the skill exists so an AI agent can *understand and update a project without
hallucinating*. A bloated skill with contradictory sentences is itself a hallucination
source (two conflicting instructions force the agent to pick one at random), so slimming
and consistency serve the same goal.

**Why now:** `tests/safe-code/README.md` already recorded the evidence (6 of 7 hard rules
are redundant with modern baseline behavior; the safe compression target is verbose
step-procedure detail, never decision points) and named the slim-down as the implication.
This release executes that recorded plan and pays down the contradictions that
accumulated across v4.1-v4.4.

**Non-goals (deferred to v4.6+, keep as backlog):** new host bridges (Windsurf, Cline/Roo,
Zed, OpenCode), vibe-coder features (`--explain` "recently done" from LOG `plain:` lines,
hook auto-install offer), pressure-test round 2, periodic context self-test between saves,
trim rules for `BACKLOG.md`/`MEMORY.md`.

## 3. SKILL.md slim-down

**Method:** compress duplicated prose in place, then extract rare-path procedure detail
into Layer-3 references. Every extracted section leaves behind a 3-6 line summary that
keeps its decision points and hard invariants inline, plus a `Layer 3 Trigger` line
naming the reference. Extracted text moves verbatim wherever possible (no meaning drift).

**Hard constraint (from tests/safe-code/README.md):** move only detail, never a decision
point. The Six-File Save Rule stays fully inline (the one rule proven load-bearing).
The `=== safe-code vX.Y session complete ===` banner line stays inline
(`check-version.sh` greps it).

### 3a. New Layer-3 references

| New file | Content moved from SKILL.md | Trigger |
|---|---|---|
| `references/save-procedure.md` | Atomic Commit Split procedure steps + commit-type mapping table; Last Session block shapes; LOG.md Trim Rule detail; Draft-Until-Save per-file sync table (Step 7) | On `/safe-code --save` |

| `references/first-run.md` | First-Run Population table + rules; Context Self-Test question set, citation/evidence rules, adversarial grading | First `/safe-code` run on an empty scaffold, or after a large drift refresh |

### 3b. In-place compressions (no reference needed)

- **Safety Invariants section** near the top: never push; never copy secrets/raw
  logs/`current-issues.md` content into committed files; never overwrite existing files
  when scaffolding/migrating/bridging; everything inside project root. Repeated
  instances elsewhere shrink to pointers.
- Provider-bridge prose stated once (Step 1 Provider Bridge is canonical); Doc Structure
  and Step 0 keep one-line pointers.
- Remote bucket table (Step 3b) compressed: all three buckets resolve to "local commit
  only", so the section states the classification in ~10 lines.
- One canonical `Reasoning:` block format (Decision Framework); per-step blocks (3c, 3e,
  3f, 4b, 5) become one-line field lists referencing it.
- Duplicate `current-issues.md` do-not-read instruction removed from Step 2a (Loading
  Layers copy is canonical).
- Step 1 scaffold file list shows one bridge line (current host), not four.
- Feature Suggestion lifecycle compressed to one line.

**Size target:** SKILL.md from 1269 lines to <= 950 (stretch 900). The earlier ~700

deeper cuts wait for pressure-test evidence (v4.6 backlog) per the tests README caveat
("redundant here != safe to delete").

## 4. Grounding Rules in the AGENTS.md template

Add a `## Grounding Rules` section to the template in
`references/agents-md-authoring.md` (and an authoring rule to preserve it when
reconciling). Rationale: bridges make every host *read* the brain, but nothing today
makes a normal (non-safe-code) session *behave* grounded. AGENTS.md is loaded by every
host on every session, so this is the highest-leverage place for anti-hallucination
discipline:

- Answer project questions from `.safe-code/context/` or the code; know which one you
  are citing.
- Verify a file, function, route, or command exists (open or grep it) before referencing
  it in an answer or edit.
- Context missing or unclear: say so and record it in `progress-tracker.md` Open
  Questions; never fill gaps with generic training knowledge.
- Repo evidence beats every doc including the context files; on disagreement, trust the
  repo and flag the mismatch.
- Never invent versions, dependencies, APIs, env vars, or team conventions not seen in
  this repo.
