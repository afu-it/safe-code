# safe-code v4.17 — Public Hardening (design)

Date: 2026-10-04 · Status: approved via grill (3 rounds + close) · Base: v4.16 (`29b1fbf`)

## Audience rule (overrides everything below)

safe-code is a **public, general-purpose skill**. Every rule added in this release must read as generic guidance for any developer on any machine:

- No personal names, account handles (except the install path `afu-it/safe-code`), client or project names, absolute home paths (`/Users/…`, `/home/<name>/…`), emails, or references to any private memory system.
- Field incidents become one-clause rationales ("a script run under the wrong shell reported 226 of ~3,700 tests with exit 0") — never named projects.
- Tool names appear only as examples in parentheses ("deploy CLIs (wrangler, vercel, fly, …)"), never as assumed setup.
- Prefer folding a rule into an existing step/bullet over adding a new section. New detail goes to `references/`, not core.

## B. Decisions from grill round 1

1. One release, **v4.17**.
2. Hook → SessionStart nudge (A1).
3. **Local-only brain, auto-detected:** `git check-ignore -q .safe-code` succeeds → `--save` updates the six files on disk (with A5 backup + line-count check), commits code tasks only, no docs commit, banner `brain: local-only (gitignored)`. Graveyard `restore:` for docs uses the backup, not `git revert`.
4. **Multi-session safety package (full):**
   - Run start (Step 3a): check for other agent sessions in this checkout (process list + cwd, `git worktree list`, dirty files no task explains, commits since last save not by this run). If found: report, and suggest a separate worktree for multi-step work.
   - Safety Invariant: never `git stash`/`stash pop`, `reset --hard`, or `checkout -- <file>` in a checkout that may be shared; to inspect an old commit use `git worktree add --detach`. Applies to subagents too.
   - `--save` (including the fallback single commit) stages **only paths this run touched**; other dirty paths are listed, never committed.
   - Step 8: unexplained changes are labelled `foreign`, **never reverted**; replace "Unexplained entries block `--save` until explained or reverted".

## C. Round 2

- **Verification (all four):** (1) a new test counts only after it is seen failing without the fix (revert/bypass → red → restore); (2) a test run passes only if the count run ≈ the known total recorded in `code-standards.md ## Testing`; a crash before counts = `inconclusive`; runner/infra crash gets one rerun → `flaky (rerun green)`; run scripts under their shebang shell; (3) `cmd | tail` hides exit status — redirect to a log + `echo exit=$?`, or `pipefail`/`PIPESTATUS`; (4) before declaring a previously working procedure broken, re-run it exactly as recorded; verifier timeouts, strict text matches, or a draft/sandbox path reading different config are verifier findings.
- **Evidence (all four):** (1) new tag `[user-confirmed: <date>]`, never upgraded to tested/extracted; user confirmation closes the related blockers; (2) no negative fact from silence — "there is no X" from absent docs/data, guessed abbreviations, and claims about what another session or the user authorised are Open Questions; (3) claims about an external API/doc enter a spec/context file only with the quoted line and the read depth (full / partial / keyword search, N lines); (4) `--continue`: one cheap probe per pending item that has something checkable (git log, merge/PR state) before presenting; close items already done.
- **Slim SKILL.md to ~600 lines** (from 985): move detail (Smoke-Verify detail, Graveyard detail, freshness/self-test detail, profile tables, Measure-Twice detail, examples) into `references/`, keep every decision point and trigger inline (v4.7 principle). All new rules land in references unless they are a decision point. Every moved block needs a Layer-3 trigger line that says when to load it.
- **Push account:** push-once token header + A8 notes. Generic wording only.

## D. Round 3 (all selected)

- **$debug-issue:** never blind-retry a side-effecting call (POST/send/migration) that failed part-way — read remote state first; check the real failing record/user state before hypothesising when read access exists; for a once-only failure with fixed inputs, look for what varies between runs (clock ties, unordered reads — ORDER BY ends on a unique column); record falsified hypotheses and failed fixes as one line each in `MEMORY.md`; cleanup closes only windows/tabs/daemons/locks the task opened, never the user's; remove stale locks only after proving no process owns them; shared credential/token stores are a contention source (concurrent refresh-token races).
- **Safety Invariants:** secret seen in the transcript → add `rotate <name>` to BACKLOG (name only); one shell command, one purpose — never chain `rm` into unrelated work; untracked files go to `.safe-code/backups/` or the OS trash, not `rm`; a version/setup the user chose is not reverted on regression — fix on top of it, offer the revert as an option; deploy CLIs ship the working tree, not the last commit — record this in the AGENTS.md toolchain quirks and check what is live before deploying an older commit (safe-code itself never deploys).
- **Repo/AGENTS.md:** tool-generated blocks (e.g. `<!-- BEGIN:nextjs-agent-rules -->…<!-- END:… -->`) are owned by the tool — write outside the markers only; Step 8 banner shows `unpushed: N` (omit when 0, `no upstream` when none); flag High: schema migrations applied outside the migration tool (tracking table out of sync) and sequential IDs (migrations, spec numbers) colliding after an upstream merge; AGENTS.md documents which gitignored env files a fresh worktree needs (key names only) — red tests in a new worktree → check env first.
- **$review-changes / spec:** test anti-patterns: substring assertions that pass/fail on negation or formatting; fake timers/jsdom hiding runtime-only bugs (needs a real-runtime probe); before a spec proposes a new module/table/harness, list what already does most of the job; changing a setting shared by several paths → check each path's time budget against real latency; performance claims need a before-baseline under the same conditions, otherwise labelled hypothesis ("fewer lines" is not evidence); test depth by change size is allowed **only when the project declares tiers in `code-standards.md`** — safe-code never picks a lighter tier itself (Proportional Ceremony compresses output, never verification).
- **Extras:** example lines inside auto-loaded instruction files get copied verbatim — include only examples you would accept word for word (`agents-md-authoring.md`); review smells: a pure helper living in a heavy module drags it into every importer (move to a leaf); two branches checking the same state with near-identical conditions leave a gap; before a vendor CLI `login`/`keys add`, check where it stores the credential and prefer env vars — warn and ask only (Scope Rule).

## Deviations (implementation)

- **SKILL.md size (C, "Slim SKILL.md to ~600 lines").** Landed at ~780 lines, not ~600. The remaining blocks are decision points or their triggers; moving more into `references/` would move decision points out of the always-loaded core, which the v4.7 principle (keep every decision point and trigger inline) forbids. Detail that is not a decision point did move (`verification.md`, `multi-session.md`, `save-reminder-hook.md`, `feature-specs.md`).
- **Claude Code bridge (A4).** The spec said: write the `CLAUDE.md` `@AGENTS.md` bridge only when a `CLAUDE.md` exists, otherwise none. Implemented: the bridge is **always** written under Claude Code. Its native `AGENTS.md` read switches off when any `CLAUDE.md` exists in the folder *or any parent*, and the Scope Rule forbids inspecting parents outside the project root — so safe-code cannot prove the native read is on, and the bridge is the only safe default.
- **Review-round fixes (post-implementation).** The hook offer writes `.claude/settings.local.json` (personal, uncommitted), not the shared `.claude/settings.json`, and uses a guarded command (`f=…; [ -f "$f" ] && bash "$f" || true`) so a removed skill never breaks session start; the script exits silently on any event other than `SessionStart`, and the old-`Stop` migration check runs on every run, not only the first. External-doc quotes and read depth live in feature specs only; auto-loaded context files keep a pointer (URL + read depth) — the quarantine rule wins over Round 2 evidence rule (3). Other-session detection excludes the agent's own process tree and counts only commits after `run_start` (HEAD recorded at Step 3a). Old commits are read with `git show <commit>:<path>` or a worktree under `.safe-code/backups/` (inside the root), not a sibling directory. The Context Self-Test re-verifies commands read-only; side-effecting commands get `check: manual`.
